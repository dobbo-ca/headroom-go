# headroom-go v0.1 — Plan 3: SmartCrusher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Run tasks SEQUENTIALLY on one shared integration-branch worktree.** No two tasks edit the same file in conflicting ways unless an explicit `dependsOn` orders them.

**Goal:** Implement the SmartCrusher MVP — the JSON-array compressor that backs `offloads.JsonOffload` — and swap the Plan-2 `passthroughCrusher{}` for the real `*smartcrusher.SmartCrusher` in `offloads.NewJsonOffload`, with **one ctor-line change in `internal/offloads`** and the new `internal/smartcrusher/**` tree. The MVP delivers: lossless compaction table (`[N]{col:type}` CSV-schema + dotted flatten + 0.30 savings gate), opaque CCR cells (comma-form marker), error/outlier/anchor preservation, the SmartSample lossy fallback (space-form marker + CCR store stash), `field_detect`, the analyzer crushability tree, and the `MAX_DEPTH=50` recursion guard.

**Architecture:** A new `internal/smartcrusher` package (plus the `internal/smartcrusher/compaction` sub-package) implements the crusher behind the existing `offloads.Crusher` seam:

```go
// internal/offloads/offloads.go (UNCHANGED — the seam)
type Crusher interface { Crush(content, query string, bias float64) CrushResult }
type CrushResult struct { Compressed string; WasModified bool }
```

`smartcrusher.SmartCrusher` implements `offloads.Crusher`. Internally it carries a **richer** 4-field result (`types.CrushResult{Compressed, Original, WasModified, Strategy}`); the seam boundary maps `crushed→Compressed`, `wasModified→WasModified` and **drops** `Strategy`/`Original`. Do **not** widen the seam type. The package decomposes 1:1 with the upstream Rust submodules (one concern per Go file), reusing the existing `internal/ccr` helpers (Store, `ComputeKey`, `ComputeKeyMD5`, the three marker builders `MarkerFor`/`MarkerForCell`/`MarkerForLossy`) and `internal/relevance` (`Scorer`, `NewHybridScorer`).

**Tech Stack:** Go 1.25. **One new dependency: `github.com/iancoleman/orderedmap`** (added in Task 1) — `map[string]any` is BANNED on the compression path; object key insertion/parse order is load-bearing everywhere. Otherwise stdlib only (`crypto/sha256`, `crypto/md5`, `encoding/hex`, `encoding/json`, `strings`, `sort`, `math`, `regexp`, `unicode`, `utf8`). cgo-free. Deterministic (no time/random on the output path).

**Authoritative behavior reference:** `docs/superpowers/research/2026-06-18-upstream-smartcrusher-behavior.txt` — a verbatim extraction of upstream `chopratejas/headroom` (`crates/headroom-core/src/transforms/smart_crusher/*`) for every subsystem (algorithms, exact constants, marker forms, edge cases). **It is the source of truth.** Sections are cited per task as `[ref: SUBSYSTEM <name>]`, `[ref: (d) constants]`, `[ref: (c) rule N]`, `[ref: PARITY_FIXTURES]`. When this plan and the reference disagree on a constant or pattern, **the reference wins** — except where this plan resolves an explicit upstream conflict (the savings gate; the two-hash opaque-cell divergence; the CCR registration path — all below).

## Shared Contract (read before any task)

### Five global porting rules (apply in EVERY task) — `[ref: (c) GO PORTING RULES]`

1. **Ordered JSON only.** Decode all JSON objects with `orderedmap.OrderedMap` (insertion/parse order preserved). `map[string]any` is BANNED on the compression path. Decode arrays as `[]any` whose object elements are `*orderedmap.OrderedMap`. Decode numbers with `UseNumber()` (`json.Number`) so `1` stays `int`-typed and `1.5` stays `float`, and so literals don't get reformatted. Iterate **ASCII-sorted keys** where the reference says "sorted" (mirrors Rust `BTreeMap`); iterate **insertion order** where it says "insertion order" (mirrors Python dict / serde Map). The shared ordered decode helper `decodeJSON` lives in `jsonutil.go` and is **created in Task 1** so every downstream task (including Tasks 4 and 9) can decode arrays-of-objects into `[]any` with `*orderedmap.OrderedMap` elements without hand-rolling a decoder.
2. **Byte length, not rune count.** Rust `.len()` on `String`/`str` is a BYTE count → Go `len(string)`. NEVER `utf8.RuneCountInString` for byte-saving math (`estimateArrayBytes`, savings-ratio numerator/denominator, `byte_size`, humanize, `len=%d`). **EXCEPTIONS where rune count IS correct** (statistical features, not byte-saving): `FieldStats.AvgLength`, `calculateStringEntropy` code points, string length-anomaly char counts. The task that owns each of these names it.
3. **THREE CCR marker forms stay THREE separate builders — do NOT unify** `[ref: (c) rule 3]`:
   - canonical `<<ccr:HASH>>` — `ccr.MarkerFor` (live-zone; NOT emitted by smartcrusher; exists already).
   - comma-form `<<ccr:HASH,KIND,SIZE>>` — `ccr.MarkerForCell` (compaction opaque cell).
   - space-form `<<ccr:HASH N_rows_offloaded>>` — `ccr.MarkerForLossy` (lossy row drop).
   Plus two non-marker SENTINEL OBJECTS this code builds: lossy-drop sentinel appended as LAST array element `{"_ccr_dropped":"<<ccr:HASH N_rows_offloaded>>"}`; constants sentinel prepended as element 0 `{"_constant_fields":{...}}` (factor-constants, default OFF). The `json_offload` bespoke wrapper `"\n[json_offload CCR: hash=<md5_24>]"` is NOT a `<<ccr:...>>` form and already exists in `json_offload.go`.
4. **Decision B — NO byte-parity.** Do NOT replicate Rust/Python float formatting (`%g`, banker's rounding, BUG#1 percentile string, padding/percentile cosmetics). Capture **behavior + ratio bounds + marker/strategy SHAPES**, not byte-exact compressed output. The four upstream Python bugs are ANTI-REQUIREMENTS — implement the CORRECT behavior: **BUG#1** proper linear-interpolation percentile; **BUG#2** zero-padded numeric strings are categorical (gate on `hadNonStringNumeric`); **BUG#3** no >10-distinct short-circuit (cardinality cap 50); **BUG#4** `kFirst+kLast` clamped `<= kTotal`. **EXCEPTION — byte-pinned identifiers** (replicate exactly): enum `AsStr()` strings, `ERROR_KEYWORDS`, hash hex, and marker structural literals.
5. **Seam = near-zero blast radius** `[ref: (c) rule 5]`. The ONLY behavioral edit outside `internal/smartcrusher/**` is the final task's one-line crusher swap in `offloads.NewJsonOffload`. `Constraint`/`Observer`/`CrushEvent`/`Scorer`/`AnchorSelector` stay INTERNAL to `smartcrusher`. Keep deferred symbols unexported with `// DEFERRED (Plan 4+):` comments. **EXPLICIT dependency-surface note (vs the "pure ccr/relevance" intent):** `smartcrusher` necessarily depends on `internal/ccr` (Store, markers, keys). To make `ccr.FromConfig(Kind:InMemory)` work, `builder.go` MUST blank-import `internal/ccr/backends` (the existing CCR design registers the in-memory constructor in `backends/inmemory.go`'s `init()`; without the blank import `ccr.FromConfig` returns `"in-memory backend not registered"` — see Task 13 fix). This widens `smartcrusher`'s import set by exactly one blank import (`backends`); it is the minimal honest path and is called out here so it is not mistaken for scope creep. No production `.go` file outside `smartcrusher/**` and the one `offloads` ctor line changes.

### Savings-gate conflict — RESOLVED for this plan `[ref: (a) SAVINGS GATE VALUE CONFLICT, config.rs, crusher.rs]`

Two upstream values exist: `config.rs` default `lossless_min_savings_ratio = 0.15` (upstream lowered it) vs `crusher.rs` doc/parity/task-brief `0.30`. **DECISION: the effective default is `0.30`** (matches `crusher.rs` + parity fixtures + brief). Make it a `Config` field `LosslessMinSavingsRatio` so tests can override to `0.99` to force the lossy path. Document the 0.15-vs-0.30 divergence in a code comment. The gate lives in `crushArray` (Task 14), NOT in compaction/formatter. Gate contract: `savings = 1 - len(rendered)/len(input)` (BYTES); `savings < LosslessMinSavingsRatio` → fall through to lossy.

### Opaque-cell hash + store-write — RESOLVED for this plan `[ref: (c) rule 3, compaction/walker.rs goPortNotes lines 1746-1749, compaction/compactor.rs hash_opaque]`

Upstream produces "opaque CCR cells" via **TWO distinct code paths with TWO different hashes**, and the reference (walker.rs goPortNotes) flags this as "TWO divergences for integrator." This plan RESOLVES it by assigning each path one hash and a single store-write rule, and by routing the round-trip-asserting fixture exclusively through the store-writing path:

- **Walker path (round-trippable).** `DocumentCompactor`/`CompactDocument`/`CompactDocumentJSON` and `processString`'s opaque branch render opaque blobs via `EmitOpaqueCCRMarker(payload, kind, store)`, which uses **`ccr.ComputeKey` (BLAKE3 → 24-hex)** and **writes the store** (`store.Put(hash, payload)`) when the store is non-nil. THIS is the only path that round-trips: `CcrGet(hash)==payload` byte-exact. The opaque-blob parity fixtures (`opaque-blob-in-object`, `compact_document_json`) MUST hit this path and are the ONLY opaque fixtures that assert round-trip.
- **Compaction-stage / Tier-2 lossless-table path (NOT round-trippable in MVP).** `cellFromValue`/`buildHomogeneousTable` build `CellOpaqueRef` cells hashed with **`hashOpaque` (SHA-256 first 6 bytes → 12-hex)** and render them via `formatCcrMarker`/`ccr.MarkerForCell`. This path **does NOT call `store.Put`** — the `CompactionStage` carries no store (see Task 11/13). These 12-hex comma-form markers are intentionally **store-orphaned and NOT recoverable via `CcrGet`** in the MVP. **No parity fixture asserts round-trip on a lossless-table opaque cell.** A blob that appears as a cell inside a Tier-2 lossless table is captured for its byte-saving (marker SHAPE only); round-trip recovery of such a cell is DEFERRED (would require threading the crusher's `ccrStore` into the compaction build — out of MVP scope, noted in Deferred).

Net rule the integrator implements and the fixtures assert:
| concept | path | hash fn | hex width | store.Put? | round-trip asserted? |
|---|---|---|---|---|---|
| opaque blob in walked value/`processString` | walker / `EmitOpaqueCCRMarker` | `ccr.ComputeKey` (BLAKE3) | 24 | YES (when store non-nil) | YES |
| opaque cell inside Tier-2 lossless table | compaction stage / `cellFromValue` | `hashOpaque` (SHA-256[:6]) | 12 | NO | NO (SHAPE only) |
| lossy row-drop (space-form) | crusher `crushArray` Tier-3 | crusher `hashCanonical` (SHA-256[:6]) | 12 | YES (gated `EnableCCRMarker`) | YES |

Tests state explicitly which fixture hits which path (Task 15). The compaction stage MUST NOT silently swallow a blob it cannot round-trip into a position where a fixture demands recovery; the fixture set in Task 15 is constructed to honor this table.

### CCR in-memory store registration — RESOLVED for this plan `[ref: (c) rule 5, builder.rs goPortNotes lines 503/532, internal/ccr/store.go, internal/ccr/backends/inmemory.go]`

`ccr.FromConfig(BackendConfig{Kind:InMemory})` returns `(nil, error)` with message `"in-memory backend not registered"` UNLESS `internal/ccr/backends` has been imported first: `backends/inmemory.go`'s `init()` calls `ccr.RegisterInMemory`, which sets the `newInMemory` constructor that `store.go` leaves `nil` otherwise. Today only `*_test.go` files and `cmd` blank-import `backends`; nothing on the production path does. So a naive `NewSmartCrusher(DefaultConfig()).Build() → WithDefaultCCRStore → FromConfig` would fail at runtime, and every `json_offload` Apply on a crushable array (after Task 16) would break.

**DECISION (path a):** `internal/smartcrusher/builder.go` adds `import _ "github.com/dobbo-ca/headroom-go/internal/ccr/backends"` so the in-memory constructor is registered whenever the smartcrusher package is linked. This is the minimal change consistent with the existing CCR design (the package is *meant* to be blank-imported per its own doc comment), and is called out against rule 5 in the dependency-surface note above. **Error handling:** `Build()` MUST NOT return an error (`builder.rs` goPortNotes line 532: defaults can't fail). `WithDefaultCCRStore` calls `ccr.FromConfig(...)`; because the blank import guarantees registration, the InMemory branch error is structurally impossible. Handle it via an internal helper `mustInMemoryStore()` that calls `FromConfig` and `panic`s only on the impossible error (programmer-error contract, documented), keeping `WithDefaultCCRStore`/`Build()` error-free. Task 13 adds a test that `NewSmartCrusher(DefaultConfig())` yields a non-nil, working store (`Put`/`Get`/`Len` round-trip).

### Two `CrushResult` shapes — do NOT conflate `[ref: SUBSYSTEM types.rs, mod.rs edgeCases]`

- `offloads.CrushResult` (seam, 2 fields: `Compressed`, `WasModified`) — exists, unchanged.
- `smartcrusher` internal `types.CrushResult` (4 fields: `Compressed`, `Original`, `WasModified`, `Strategy`) — new, internal. Conflating them is the #1 porting error.

### Two value-stringifiers — distinct funcs, do NOT merge (would not compile) `[ref: anchors.rs lines 1249/1272, analyzer.rs lines 793-794]`

Two upstream helpers are both called "python_repr" but render objects/strings DIFFERENTLY; in one Go package they MUST have distinct names or `pythonRepr redeclared` is a compile error. They are intentionally separate:
- **`pythonRepr(value any) string`** (ships in `anchors.go`, Task 6) — Python-str style: `None`/`True`/`False`, strings **always single-quoted** (`'s'`), arrays `[a, b]`, objects `{'k': v}` (single-quoted keys, insertion order). Used for query-anchor SUBSTRING matching (`ItemMatchesAnchors`). The whole reason it exists: anchor `none` matches `{'val': None}` but `null` does not.
- **`cardinalityRepr(value any) string`** (ships in `analyzer.go`, Task 8) — cardinality/uniqueness KEY only: `None`/`True`/`False`, `Number`→token, `String`→raw (NOT quoted), **Object/Array→JSON** (`json.Marshal`, NOT Python single-quote form). Used solely to dedup field values for `unique_count`/`max_uniqueness`. NOT a matcher; never substring-tested against anchors.

These are NOT mergeable (single-quote Python objects vs JSON objects; quoted vs raw strings) and NOT the same function. `anchors.go` keeps `pythonRepr`; `analyzer.go` MUST name its cardinality stringifier `cardinalityRepr` (or another distinct unexported name) and carry a one-line comment that it is NOT `anchors.go`'s `pythonRepr`.
