(c) GO PORTING RULES (apply everywhere)
----------------------------------------------------------------------------------------------------
  (1) ORDERED JSON: use github.com/iancoleman/orderedmap for ALL JSON objects on the compression
      path. map[string]any is BANNED. Object key insertion order is load-bearing (process_value
      first-pass recursion, python_safe_json_dumps, _constant_fields/_ccr_dropped sentinel placement,
      uniform_object_keys ORDERED-slice equality, column order). NOTE: orderedmap is NOT yet in
      go.mod — Plan 3 adds github.com/iancoleman/orderedmap.
  (2) BYTE LENGTH: Rust .len() on String/str is a BYTE count -> Go len(string). NEVER
      utf8.RuneCountInString for byte-saving math (estimate_array_bytes, savings_ratio numerator/
      denominator, observer input/output_bytes, rendered.len() "len=%d", byte_size, humanize input,
      token estimates). EXCEPTIONS where rune/char count IS correct (statistical length features, NOT
      byte-saving): FieldStats.avg_length (chars().count()), crush_string_array length-anomaly
      (chars().count()), calculate_string_entropy (code points). Cluster-hash uses .chars().take(50)
      (char count) but is DEFERRED.
  (3) THREE CCR MARKER FORMS — keep as THREE SEPARATE builders, do NOT unify:
        - canonical (live-zone):    <<ccr:HASH>>                       (NOT emitted by smart_crusher
                                                                        files; built elsewhere)
        - comma-form (compaction opaque cell):  <<ccr:HASH,KIND,SIZE>>  e.g. <<ccr:abc,base64,4.5KB>>
        - space-form (lossy row drop):          <<ccr:HASH N_rows_offloaded>>
                                                e.g. <<ccr:89f81e97033e 15_rows_offloaded>>
      Non-marker SENTINEL OBJECTS this code also builds (NOT <<ccr:...>> forms):
        - lossy-drop sentinel appended as LAST array element: {"_ccr_dropped":"<<ccr:HASH N_rows_offloaded>>"}
        - factor-constants sentinel prepended as element 0:   {"_constant_fields":{...}}
        - json_offload bespoke wrapper marker (NOT a <<ccr:...>> form):
            "\n[json_offload CCR: hash=<md5_hex_24>]"
  (4) DECISION B — NO BYTE-PARITY: do NOT replicate Rust/Python float formatting (%g, banker's
      rounding, BUG#1 percentile string, padding/percentile cosmetics). Capture behavior + ratio
      bounds + marker/strategy SHAPES, not byte-exact compressed output. The four upstream Python
      bugs are ANTI-REQUIREMENTS in Go (implement the CORRECT behavior):
        BUG#1 percentile: use proper linear-interpolation percentile (numpy 'linear'), not int-div idx.
        BUG#2 sequential: zero-padded numeric strings (e.g. ["001".."010"]) are NOT sequential
              (categorical) — gate on hadNonStringNumeric.
        BUG#3 rare-status: NO >10-distinct short-circuit — cardinality cap raised to 50.
        BUG#4 k-split: k_first+k_last clamped to <= k_total (respect max_items_after_crush).
      EXCEPTION: enum as_str() strings ("dict_array","smart_sample","cluster","top_n", etc.),
      ERROR_KEYWORDS, hash hex, and marker structural literals ARE byte-pinned (identifiers, not
      float formatting) — replicate exactly.
  (5) SEAM (zero-blast-radius): existing internal/offloads:
        type Crusher interface { Crush(content, query string, bias float64) CrushResult }
        type CrushResult struct { Compressed string; WasModified bool }
      The seam CrushResult has NO Strategy/Original field. SmartCrusher internally computes
      (compressed, wasModified, info) and maps crushed->Compressed, wasModified->WasModified at the
      boundary (info/strategy dropped). Plan 3 swaps passthroughCrusher{} -> *SmartCrusher in
      offloads.NewJsonOffload (json_offload.go) with ZERO changes to other packages. The internal
      types.CrushResult is RICHER (4 fields: Compressed/Original/WasModified/Strategy) — keep it
      INTERNAL, do NOT widen the seam type.
